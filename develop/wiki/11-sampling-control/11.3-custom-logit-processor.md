# 11.3 自定义 logit processor

## 定位

`CustomLogitProcessor` 是采样控制链中"用户可注入"的扩展点。它允许调用方把任意 `torch.Tensor → torch.Tensor` 的 Python 可调用对象塞进采样管线，在 `Sampler._preprocess_logits` 之前先于 temperature/penalty/grammar 修改 logits。为了跨进程（TokenizerManager → Scheduler）传输一个 Python 对象，SGLang 用 `dill` 序列化并以 JSON 包装的 hex 字符串走过 msgpack IPC。

## 职责

- `CustomLogitProcessor` ABC：定义 `__call__(logits, custom_param_list)` 接口与 `to_str`/`from_str` 序列化对，`from_str` 用 `lru_cache` 复用反序列化结果。
- 三个内置 processor：`DisallowedTokensLogitsProcessor`（屏蔽一批 token）、`ThinkingBudgetLogitProcessor`（按思考预算强制 `think_end` token）、`DeepseekOCRNoRepeatNGramLogitProcessor`（n-gram 不重复）。
- `apply_custom_logit_processor`（位于 [11.4](11.4-sampler-layer.md)）按 batch mask 选出归属行并调用对应处理器。

## 数据流 / 控制流

```mermaid
flowchart LR
    USER["用户 Python 类<br/>继承 CustomLogitProcessor"] --> TS["to_str:36<br/>dill.dumps hex"]
    TS --> IPC["JSON 字符串过 msgpack IPC"]
    IPC --> FSB["from_schedule_batch:82<br/>按 processor_str 哈希分组"]
    FSB --> DICT["custom_logit_processor dict<br/>hash->(processor, bool mask)"]
    DICT --> ACL["apply_custom_logit_processor:742"]
    ACL -->|"batch_mask nonzero"| CALL["processor.__call__(logits[mask], custom_params)"]
    CALL --> MOD["就地修改 logits"]
```

`SamplingBatchInfo.from_schedule_batch` 把相同 `processor_str` 的请求合并，记录各自在 batch 中的 `bool mask`；`to_str`/`from_str` 保证同一字符串在 scheduler 侧只反序列化一次（`_cache_from_str` 的 `lru_cache`）。`ThinkingBudgetLogitProcessor` 通过 `custom_params[i]["__req__"]` 拿到 `Req`（在 scheduler 进程内由 `Req.__init__` 注入，不再二次序列化），据此统计思考段长度并在预算耗尽时把整行 logits 置 -inf、仅放开 `THINKING_END_TOKEN_ID`。`DisallowedTokensLogitsProcessor` 要求 batch 内所有请求的 `token_ids` 一致，因此合并分组时同一处理器下的请求需共享同一禁用集。
