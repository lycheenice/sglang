# 14.5 Multiplex

## 定位

`multiplex/` 让单个 GPU 进程里同时跑多个"虚拟 scheduler"——典型场景是 PD 复用（prefill 与 decode 同进程不同流组），或同卡多模型。`SchedulerMultiplexMixin` 挂在 `Scheduler` 继承链上，`pdmux_context.py` 管理流组与 SM 切分。它是 [09 分离](../09-disaggregation/index.md) 同进程复用形态与未来多租户复用的基础。

## 职责

- `SchedulerMultiplexMixin`（`multiplex/multiplexing_mixin.py:32`）给 `Scheduler` 加"按 mux 上下文 dispatch forward / batch"的能力。
- `PDMuxConfig`（`multiplex/pdmux_context.py:15`）描述 PD 复用的 SM/流组划分；`load_pdmux_config` 从文件加载。
- `get_arch_constraints`/`divide_sm` 按 GPU compute capability 把 SM 数切成多组。
- `initialize_stream_groups` 在 GPU 上建一组 (compute, comm) stream 对；`set_current_stream_idx`/`get_current_stream_idx` 选当前 mux 用的流组；`get_stream_groups`/`get_sm_counts` 暴露给上层。
- 与 [`08 分布式`](../08-distributed/index.md) 的并行组、[`04 模型执行`](../04-model-execution/index.md) 的 forward context 协同：每次 forward 切到对应流组与 SM mask。

## 数据流 / 控制流

```mermaid
flowchart LR
    CFG[PDMuxConfig] --> DIV[divide_sm 切 SM 组]
    DIV --> INI[initialize_stream_groups]
    INI --> SG[(compute,comm) stream 对组]
    SCH[SchedulerMultiplexMixin] -->|forward 前| SET[set_current_stream_idx]
    SET --> SG
    SG --> CTX[ForwardContext 用本组流 + SM mask]
    CTX --> FW[本 mux 的 forward]
    FW -->|完成后| REL[恢复默认 stream idx]
```

PD 同进程复用下，prefill mux 与 decode mux 各占一组 SM 与独立 stream；scheduler 在切到某 mux 时把 `ForwardContext` 的默认 stream 换成该组 compute stream，attention/MoE 通信走该组 comm stream。SM mask 经 kernel launch config 或 `cudaStreamAttr` 限定，避免互相抢 SM。这种形态相对跨进程 PD 省去 RDMA 与 bootstrap 开销，代价是共享 GPU 显存与 SM，适合中等吞吐的合部署。
