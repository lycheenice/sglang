# 16.2 server_args_config_parser

## 定位

`server_args_config_parser.py` 让 SGLang 支持用 YAML 文件提供 `ServerArgs` 配置：`--config file.yaml`。`ConfigArgumentMerger` 把 YAML 内容转成 CLI 参数并按 `CLI > Config > Defaults` 的优先级合并进 argv，随后交给 [16.1 prepare_server_args](16.1-server-args-port-args.md) 的 argparse 正常解析。本模块刻意只做"参数拼接"，不直接构造 `ServerArgs`，因此所有 dataclass 字段语义保持单一入口。

## 职责

- 从 argv 中定位 `--config`（仅允许一个），校验后缀为 `.yaml`/`.yml`。
- `yaml.safe_load` 读取配置字典，按字段类型转 CLI 标志：布尔（区分 `store_true`）、list、dict（`json.dumps`）、标量。
- `store_true` 字段 True→加标志、False→跳过；普通布尔→`--key true/false`。
- 把转换后的 config 参数插在 `--config` 之前的子命令之后，使 CLI 显式参数覆盖 config。
- 拒绝 argparse 中非 `store_true`/`store` 的 action（如 count/append），避免静默误用。

## 子模块树

- `python/sglang/srt/server_args_config_parser.py` — 单文件模块，仅依赖 `argparse`/`yaml`/`json`/`pathlib`

## 数据流 / 控制流

```mermaid
flowchart LR
    ARGV["原始 argv"] --> EXT["_extract_config_file_path"]
    EXT --> YAML["_parse_yaml_config yaml.safe_load"]
    YAML --> CONV["_convert_config_to_args dict→flags"]
    CONV --> SPLIT["按 --config 位置切分 argv"]
    SPLIT --> MERGE["config_args + before + after"]
    MERGE --> OUT["合并 argv → argparse"]
    OUT --> SA["16.1 ServerArgs __post_init__"]
```

`merge_config_with_args` 先抽 `--config` 路径，无则原样返回；读取 YAML 后 `_convert_config_to_args` 遍历字典，布尔字段特判 `store_true`，dict 值 `json.dumps` 成字符串。最终把 config 参数拼在 `--config` 前的子命令之后、CLI 显式参数之前，保证 `CLI > Config > Defaults`。`unsupported_actions` 会在转换时就抛错，防止用 config 触发 argparse 不支持的 action 类型。
