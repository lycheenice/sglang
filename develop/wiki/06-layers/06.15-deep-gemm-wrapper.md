# 06.15 deep_gemm_wrapper

## 定位

`layers/deep_gemm_wrapper/` 是 SGLang 对 DeepGEMM 库（FP8/FP4 grouped-GEMM）的统一门面。它把 JIT 编译、warmup、num-SM 配置、kernel 选择封装出来，给 [`06.4.3 MoeRunner`](06.4.3-moe-runner.md) 的 `DeepGemmRunnerCore` 与 [`06.4.1 FusedMoE`](06.4.1-moe-module-flow.md) 的 deferred finalize 路径提供一组干净的入口。

## 职责

- `entrypoint.py` 暴露 grouped GEMM 入口：`grouped_gemm_nt_f8f8bf16_masked`、`grouped_gemm_nt_f8f8bf16_contig`、`grouped_gemm_nt_bf16_masked` / `_contig`、`gemm_nt_f8f8bf16`、`gemm_nt_mxfp8_f8f8bf16`、`gemm_nt_bf16bf16f32`、`tf32_hc_prenorm_gemm`。
- `compile_utils.py`：DeepGemm kernel 分类（`DeepGemmKernelType:101`）、JIT 编译（`_maybe_compile_deep_gemm_one_type_all:114` / `_compile_deep_gemm_one_type_all:159`）、warmup executor（`_BaseWarmupExecutor:230` 及若干子类）。
- `configurer.py`：`_compute_enable_deep_gemm:17` 与 `ENABLE_JIT_DEEPGEMM` 全局开关（依赖 `envs.SGLANG_ENABLE_JIT_DEEPGEMM`）。
- `update_deep_gemm_config`：把 `ServerArgs` 的 deep_gemm 选项写入运行时配置。
- `pp_parallel_deep_gemm_warmup:421`：流水并行下的 warmup 入口。

## 数据流 / 控制流

```mermaid
flowchart LR
    ENV["envs.SGLANG_ENABLE_JIT_DEEPGEMM"] --> CFG["_compute_enable_deep_gemm:17"]
    CFG --> EN["ENABLE_JIT_DEEPGEMM:35"]
    EN --> ENTRY["entrypoint.py if ENABLE_JIT_DEEPGEMM"]
    ENTRY --> CMP["_maybe_compile_deep_gemm_one_type_all:114"]
    CMP --> WARM["_BaseWarmupExecutor:230 → 各 warmup 子类"]
    WARM --> RK["DeepGemmRunnerCore:140 (moe_runner/deep_gemm.py)"]
    RK --> GEMM["grouped_gemm_nt_f8f8bf16_masked:27 / _contig:112"]
    GEMM --> OUT["MoE expert output"]
    SA["ServerArgs"] --> UDC["update_deep_gemm_config:49"]
    UDC --> CFG
```

启动期 `configurer._compute_enable_deep_gemm` 读 `SGLANG_ENABLE_JIT_DEEPGEMM` 决定是否启用 JIT；启用时 `entrypoint` 调 `_maybe_compile_deep_gemm_one_type_all` 把所有 `DeepGemmKernelType` 编译并 warmup。运行期 `DeepGemmRunnerCore.run_moe_core` 选对应的 grouped GEMM 入口（FP8/FP4/BF16）送 token+expert weight，结果回到 `FusedMoE` 主流程。`pp_parallel_deep_gemm_warmup` 在 PP>1 时按阶段预热。
