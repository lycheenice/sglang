# 17.3 前向指标 FPM

## 定位

`observability/forward_pass_metrics.py` 提供"每迭代调度器内部状态"的实时广播通道，补足 Prometheus 的轮询模型。`SchedulerMetricsMixin._emit_forward_pass_metrics` 把 `ForwardPassMetrics` 序列化后经 ZMQ PUB（localhost）发出，外部消费者（典型为 NVIDIA Dynamo）用 ZMQ SUB 接收，免轮询观察调度行为。`FPM_VERSION=1` 为 schema 版本。

## 职责

- `WelfordAccumulator`：在线 count/total/方差累积，数值稳定单 pass，用于每迭代 accept length 等聚合。
- `ScheduledRequestMetrics`/`QueuedRequestMetrics`：单请求维度快照（msgspec.Struct，zero-copy）。
- `ForwardPassMetrics`：单次迭代的完整指标（运行/队列请求、token 池、spec、retract 等）。
- `encode`/`decode`：msgspec 编解码，`FPM_VERSION` 保证消费端兼容。
- `_FpmPublisherThread`：后台线程从 queue 取 metrics 序列化并 ZMQ PUB 发送。
- `SchedulerMetricsMixin`（Scheduler 侧 mixin）按迭代填充并发射。

## 数据流 / 控制流

```mermaid
flowchart LR
    SCH["Scheduler 事件循环"] --> MIX["SchedulerMetricsMixin._emit_forward_pass_metrics"]
    MIX --> FPM["ForwardPassMetrics:97 填充"]
    FPM --> ENC["encode:127 msgspec"]
    ENC --> Q["内部 queue"]
    Q --> PUB["_FpmPublisherThread:135"]
    PUB --> ZMQ["ZMQ PUB localhost"]
    ZMQ --> SUB["外部 ZMQ SUB（Dynamo 等）"]
    SUB --> DEC["decode:131 FPM_VERSION 校验"]
    DEC --> CONS["实时仪表/告警"]
```

Scheduler 每迭代把 `ForwardPassMetrics` 投给 `_FpmPublisherThread` 的内部 queue，后台线程序列化后经 ZMQ PUB 发出。消费者 ZMQ SUB 接收、`decode` 校验 `FPM_VERSION` 后用。schema 不兼容时必须 bump `FPM_VERSION`。这与 [17.1 Prometheus metrics](17.1-prometheus-metrics.md) 互补：FPM 是 push-based 低延迟内部通道，Prometheus 是 pull-based 聚合通道。
