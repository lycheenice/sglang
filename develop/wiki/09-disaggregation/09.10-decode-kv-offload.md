# 09.10 Decode 侧 KV 卸载

## 定位

`disaggregation/decode_kvcache_offload_manager.py` 在 decode server 上为已收 KV 提供 L2 host pool 卸载与按需回填，避免长上下文 decode 把 GPU HBM 撑爆。它与 [`07 KV Cache`](../07-kv-cache/index.md) 的 `HiCacheController`（`managers/cache_controller.py`）和 `kv_cache_builder.maybe_register_hicache_draft` 协同，并通过 [09.7](09.7-kv-events-bridge.md) 的事件流感知 block 存废。

## 职责

- `DecodeKVCacheOffloadManager` 持有 `req_to_token_pool`、`token_to_kv_pool_allocator`、`tree_cache` 与 TP group，在 decode 侧建主机侧 `decode_host_mem_pool`（MHA 或 MLA host pool）。
- `offload_stride` 由 `SGLANG_HICACHE_DECODE_OFFLOAD_STRIDE` 控制，默认按 page_size 对齐，决定多久做一次卸载。
- 借 `HiCacheController`（`cache_controller.py:225`）做 GPU↔host↔disk 的存储栈与预取预算；`HiCacheStorage`/`HiCacheFile`/外部存储介质 → `StorageMedium` 事件。
- 与 `decode_hicache_mixin.py` 的 `DecodeHiCachePreallocMixin`/`DecodeHiCacheTransferMixin`/`HiCacheRestoreGatedKVReceiver` 配合，在请求准入与 GPU forward 之间门控回填。
- `kv_cache_builder.maybe_register_hicache_draft` 在 KV cache 构建期注册可能与 draft 模型共享的 hicache draft 槽。

## 数据流 / 控制流

```mermaid
flowchart LR
    DS[Decode Scheduler] --> ADM[DecodeKVCacheOffloadManager]
    ADM --> HP[decode_host_mem_pool<br/>MHA/MLA host]
    HP <-.写回/回填.-> GPU[GPU KV pool]
    CC[HiCacheController] -->|预算/淘汰| HP
    CC --> DS[Storage[StorageMedium: GPU/CPU/DISK/EXTERNAL]]
    EVT[BlockStored/Removed 事件 09.7] --> CC
    DS -->|准入| PRE[DecodeHiCachePreallocMixin 预分配]
    DS -->|forward 前| RST[HiCacheRestoreGatedKVReceiver 回填门控]
    RST --> GPU
```

卸载/回填粒度对齐 `page_size`：decode 侧每生成若干 token 即把稳定 page 写回 host pool，由 `HiCacheController` 决定何时再下沉到 disk 或外部（`EXTERNAL`，如 Mooncake 共享池）。请求准入时若前缀已在 host/disk 命中，`HiCacheRestoreGatedKVReceiver` 会在 forward 前把对应 page 回填到 GPU 空槽，再让 disagg receiver 复用——从而 prefill↔decode 传输与 hicache 回填共担同一套 KV pool 槽位管理。
