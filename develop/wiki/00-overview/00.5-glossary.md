# 00.5 术语表

## 定位

本页收录 SGLang 架构 Wiki 中反复出现的核心术语，给出简短定义与在仓库中的对应位置。术语顺序按"推理机制 → 内存/缓存 → 并行 → 调度/执行"分组，便于主题式检索。

## 推理与解码机制

| 术语 | 说明 |
|---|---|
| RadixAttention | 以基数树组织 KV Cache 的前缀复用机制。相同前缀的请求共享已算出的 KV，避免重复 prefill。SGLang 的招牌特性，实现于 `srt/managers/radix_cache.py`（详见 [`07 KV Cache`](../07-kv-cache/index.md)） |
| 连续批处理 continuous batching | 不等整批完成，每步都可把新请求并入活跃 batch 的调度策略；配 Prefill/Decode 混批实现高吞吐。见 [`03 编排`](../03-orchestration/index.md) |
| Prefill-Decode 分离 | 把长 prompt 的 prefill 与短步 decode 分别调度、甚至分到不同进程/实例（PD 分离），消除 prefill 对 decode 的尾延迟干扰。见 [`09 分离式推理`](../09-disaggregation/index.md) |
| 投机解码 speculative decoding | 用小 draft 模型/启发式投机若干 token，再由大模型一次验证，提升解码吞吐。SGLang 支持 EAGLE/DFlash/Spec V2/N-gram/MTP。见 [`10 投机解码`](../10-speculative/index.md) |
| chunked prefill | 把超长 prefill 切成多块与 decode 交替执行，避免单条长请求长时间占用 GPU。见 [`03 编排`](../03-orchestration/index.md) |
| overlap scheduling | CPU 调度与 GPU forward 重叠：在 GPU 跑当前 batch 时 CPU 已备好下一批，逼近零开销调度。见 [`03 编排`](../03-orchestration/index.md) |
| 受限解码 constrained decoding | 在生成时按正则/JSON schema/grammar 约束采样，保证输出结构合法。见 [`11 采样与解码控制`](../11-sampling-control/index.md) |
| structural tag / structured output | 通过受限解码或压缩 FSM 强制产出 JSON/HTML 等结构化文本的同义概念簇 |

## 注意力与模型结构

| 术语 | 说明 |
|---|---|
| MLA | Multi-head Latent Attention，DeepSeek 系列的低秩 KV 压缩注意力，显著降 KV 显存。SGLang 有 TRT-LLM MLA 等后端实现 |
| MoE | Mixture-of-Experts，专家混合模型：每 token 仅激活部分专家。SGLang 支持专家路由与 EP。见 [`06 Layers`](../06-layers/index.md) |
| Paged Attention | 把 KV 显存按物理块（page）组织并按需分配，类似 OS 分页，消除碎片。见 [`07 KV Cache`](../07-kv-cache/index.md) |
| HiCache | 多级 KV 缓存：热前缀留 GPU、温前缀下沉 CPU/磁盘，按需上提，扩展可复用前缀总量。见 [`07 KV Cache`](../07-kv-cache/index.md) |
| CUDA graph | 把一组 kernel 调用预先捕获为图，运行期重放以降 CPU 开销。Decode 阶段常用。见 [`04 模型执行`](../04-model-execution/index.md) |

## 并行与分布式

| 术语 | 说明 |
|---|---|
| TP | Tensor Parallel，张量并行：把同一层权重切到多卡联合计算。见 [`08 分布式`](../08-distributed/index.md) |
| PP | Pipeline Parallel，流水线并行：把不同层段分到不同卡，按微批次流水。见 [`08 分布式`](../08-distributed/index.md) |
| DP | Data Parallel，数据并行：多份完整副本各自处理不同请求，由 `DataParallelController` 调度。见 [`00.4 进程模型`](00.4-process-model.md) 与 [`08 分布式`](../08-distributed/index.md) |
| EP | Expert Parallel，专家并行：把 MoE 不同专家分布到多卡，配 scale join 模式。见 [`08 分布式`](../08-distributed/index.md) |
| CP | Context Parallel，上下文并行：把超长序列分片到多卡协同算注意力。见 [`08 分布式`](../08-distributed/index.md) |
| PD 分离 | Prefill 实例与 Decode 实例分离部署，KV 经 Nixl/Mooncake 跨进程/跨机传输。见 [`09 分离式`](../09-disaggregation/index.md) |

## 前端与运行时

| 术语 | 说明 |
|---|---|
| SRT | SGLang Runtime，即服务端运行时（`python/sglang/srt/`），与前端 DSL（`lang/`）相对 |
| DSL | 前端领域语言，用 `sgl.function`/`sgl.gen` 等原语编写可 traced 的提示程序。见 [`01.5 前端 DSL`](../01-frontend/01.5.1-dsl-api.md) |
| Engine | 两条含义：`sgl.Engine`（客户端 API）；`srt.entrypoints.engine.Engine`（运行时引擎类，组合三组件）。见 [`00.4 进程模型`](00.4-process-model.md) |
| RuntimeEndpoint | DSL 前端连到已部署 SRT 服务端点的主要 backend，HTTP 调 SRT。见 [`01.6 前端后端`](../01-frontend/01.6-fe-backends.md) |
| Pythonic function call | SGLang 对 tool/function call 的一种解析风格，见 `srt/function_call/`（[`11 采样与解码控制`](../11-sampling-control/index.md)） |
